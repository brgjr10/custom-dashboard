Custom Dashboard

A configurable home server dashboard with modular widgets, drag-and-drop layout, theme support, and a local-first architecture. Built for reliability, readability, and speed.

Themes

How It Works

The dashboard is split into three layers: the Express backend serves static assets and proxies local/external APIs; the widget engine fetches data and renders cards; the config layer persists layout and preferences in localStorage. All three communicate through a small, explicit API surface so the frontend stays framework-agnostic and the backend stays replaceable.

│  config.js  │     │  Static files│     └──────────────┘

                           │
                    ┌──────▼──────┐
                    │  External   │
                    │  APIs       │
                    │  GitHub,    │
                    │  Open-Meteo │
                    └─────────────┘

server.js serves the public/ folder, owns all routing, and centralizes cross-cutting concerns: auth, caching, and error formatting. Widgets never call external services directly; they go through /api/* so credentials stay server-side.

Data Flow

On startup, config.js loads persisted settings from localStorage (or falls back to public/data/widgets.json). app.js builds the grid from that config, instantiates each widget class from widgets.js, and starts per-widget refresh timers based on the global or per-widget interval. When a widget loads, it calls its own fetchData(), which hits an Express route; the route returns normalized JSON; the widget’s format() turns that into HTML.

Features

⚡ Real-time Widgets

System stats, Docker health, network info, speed tests, weather, and GitHub activity with configurable refresh intervals.

🎨 Theme System

12 built-in themes using CSS custom properties. Switch instantly; preference persists across sessions.

🗂️ Drag & Drop Layout

Arrange widgets in a CSS Grid. Resize from corners, reorder by dragging, and export/import layouts as JSON.

🔒 Optional Auth

Enable basic HTTP auth with AUTH_USER and AUTH_PASS environment variables. Disabled by default for local use.

📦 Zero Build Step

Served directly from Express with ES modules. No bundler required for the frontend; backend caching reduces external API hits.

🐳 Docker Ready

Runs in Docker with host networking and privileged mode for nsenter/Docker socket access. Secrets via .env.

Setup

git clone https://github.com/brgjr10/custom-dashboard.git
cd custom-dashboard
cp .env.example .env
# edit .env with your GITHUB_TOKEN, AUTH_USER, AUTH_PASS
docker compose up -d --build

Or run locally:

npm install
npm run dev

Widget System

Every widget extends the base Widget class with three methods:

  • fetchData() — returns a Promise that resolves to widget data
  • format(data) — returns an HTML string for the widget body
  • render() — creates the DOM element with header, content, and footer

Add a new widget by creating a class in public/js/widgets.js, registering it in WIDGET_CLASSES, and adding a config entry in public/data/widgets.json.

Configuration

Layout and widget settings are stored in localStorage as JSON. On first visit, the dashboard falls back to public/data/widgets.json. Global settings include theme, unit (°C/°F), and dashboard refresh interval. Per-widget settings include position, size, and refresh interval overrides.

Developer Experience

Run npm run dev for hot-reload via nodemon. Frontend files are ES modules with explicit imports, making the dependency graph clear and enabling tree-shaking in future bundler migrations. Caching and auth are cross-cutting concerns in server.js, so they apply uniformly without touching widget code.
